# Contributing

Thanks for looking. Topping Out is small and run by one person, so the most useful help is specific.

## Most wanted

- **Reports from macOS and Linux.** It's tested on Windows 11 with Claude Code as the foreman. CI runs the scripts' self-tests on all three systems, but a full job hasn't been run on macOS or Linux yet. If you try one, open an issue with what happened, good or bad.
- **Where it broke for you.** Use the "Something didn't work" issue template: what you ran, what you expected, what happened, your setup.
- **A rule that saved you.** Every rule in `RULES.md` exists because something went wrong once. If you have one, open an issue with the story.

## Changing the package

1. Fork, branch, and keep one change per pull request.
2. Run the checks for what you touched. CI runs all of these on every pull request:
   - `node skills/f-setup/install.mjs --self-test`
   - `node skills/f-signoff/endgame.mjs --self-test`
   - `node skills/f-comply/comply.test.mjs`
   - `python skills/f-board/test_render_board.py`
3. `docs/` is the website and is generated by `scripts/build_site.py`. Edit the sources, never the pages.
4. House style: plain language, no em dashes, and every claim backed by a file, a command or a commit. Never name a builder's model or vendor in records (`RULES.md`).

## Security

Please report security problems privately, through the repo's Security tab (`.github/SECURITY.md`), not in an issue.
