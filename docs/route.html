Words used on this page

Words used

Ticket
One piece of work from the plan. One job builds one ticket.
Blueprint
The full plan for a project, written before any code.
Work order
A short, exact instruction the foreman writes for the builder: one task, the commands to run, the code it starts from.
Worktree
A separate working copy of the repo, so a job's changes never touch your main copy until they are merged.
VP
A verification point: something that must be true when the work is done, with the way to check it.
t0
The test results captured before any change, so every later result can be compared with them.
Base versus head
Running the tests on the code before the job (base) and after it (head), to see exactly what the job changed.
Gate 1, gate 2
Check points the job must pass: gate 1 checks the job's plan, gate 2 the finished build.
Cold read
A review by someone who did not see the work being made, so it shares none of its assumptions.
Model family
AI models from one company. A reviewer from another family has different blind spots.
Pull request (PR)
A request to merge the job's branch, where the change is reviewed before it lands.
Greptile
An automated pull-request reviewer. It reviews each pull request, up to three rounds.
Acceptance ledger
Every requirement with its check and its result. Every row must pass before the job closes.
Opener, handover
What one session leaves the next: a short opener to paste, and the notes on where the job ended.
D- decisions
Design decisions in the plan, labelled D- and a letter, each settled down to the exact detail before a work order uses it.
H1 to Hn
The hostile inputs a work order lists for its task, such as missing keys or wrong types. Each one needs a test.
G1 to G6
The standard gap checklist in every work order: cancellation, deadlines, fields reaching their destination, every error path tested, many-item cases, typed errors for bad input.
HEAD
The latest commit on a branch. A work order names the exact one it starts from.
