# Repo profile

One file per product, kept in the records repo (`<records>/REPO-PROFILE-<product>.md`). Every opener points to it, so no session has to guess the environment.

| Field | Value |
|---|---|
| Method root (this folder, absolute) | `<path to the installed method folder, foreman/method/>` |
| Records repo | `<path>` (jobs, work orders, reviews, `foreman/projects/`, `foreman/logbook/`) |
| Constitution | `<AGENTS.md or CLAUDE.md>`: where `/f-distill` promotes product lessons (on the owner's word) |
| Plans and scratch folders | **fixed conventions, not settings:** ready-to-build plans in `foreman/blueprints/ready/` (`/f-blueprint` writes there, `/f-plancheck` gates there), ideas in `foreman/ideas/`, and a gitignored `scratch/` at the repo root (f-plancheck, the councils and speak write there). Add `scratch/` to `.gitignore` |
| Measurement / eval harness | `<name and command, or none>`: named here so plans validate it before any paid run |
| Target repo | `<path>`, remote `<remote>` (usually `origin`), main branch `<main>` (usually `main`). Every template writes `<remote>/<main>`; the foreman fills in the real name in each work order |
| Worktree tool and root | `<orca / git worktree>`, `<path>` |
| Shell for work orders | **Bash is required** for every command in a work order (Git Bash on Windows): the templates use Bash variables, `env -u`, process substitution and `comm`. The builder may explore in any shell |
| Gates (exact commands) | `<runner paths>`, or the repo's own gate, e.g. `python -m unittest discover -s tests -t .`. **Whole-suite gate:** its name and paths in the runner (`run_full_gate <name> <paths>`, e.g. `g1_tests tests`): base-vs-head reuses a t-final capture by that name. **Left out of it:** `<marker, e.g. load>`, run by hand with `<command>` (`templates/TEST-ADAPTERS.md`, "Slow tests stay out of the gate"), or `none` |
| Test adapter | runner `<pytest / unittest / jest / vitest / go test / cargo test / other>`; its three Bash functions `run_tests`, `failed_ids`, `ran_ok` in `<records>/test-adapter.sh` (copied from `templates/TEST-ADAPTERS.md`, proved on a fixture before the first job), the branch-coverage command, and how new tests run against the previous commit's code |
| Test time | one whole-suite run: `<n> min` measured `<date>` (from a run summary); the slowest tests from the adapter's `--durations` output. **Hang guard:** `TEST_TIMEOUT` `<seconds, about twice one whole-suite run>` in the adapter (`timeout` found: yes / no). **Whole suite every work order:** `yes` under about 5 minutes, else `no` (the whole suite runs once, at the final head; `METHOD.md` §7) |
| CI runs the whole suite | `yes`: CI runs every test on every PR (`<workflow file>`, about `<n> min`), so it is the job's second whole run and t0 reads main's CI (`METHOD.md` §8 step 6); `no`: t0 and the foreman run the whole suite here (`WHOLE_AT_T0=1` in the gate runner) |
| Base green here | `yes` / `no`: the whole suite on a clean main on this machine fails 0 tests (measured `<date>`); `no` lists them, and a sweep job on the board makes it `yes` (`Foreman-Playbook.md`, "A red baseline") |
| Parallel workers | per machine: the machine, its `foreman/.test-workers` number, and the last line of `snippets/parallel_proof.sh` (`PROVED <date>: ...`), or `one process: <not proven / NOT PROVED line>`. Changing the test setup (a new shared database, a fixed port) means proving again |
| Dirty-file allowlist | `<files that may be dirty in a worktree and are never staged, e.g. an untracked lockfile; or none>`. Every state check in a work order expects exactly this list |
| Paid keys to strip on every run | `<ENV_VAR_1>`, `<ENV_VAR_2>` |
| Disposable databases / services | `<name:port>` (never the shared one: `<name:port>`) |
| Database change paths | `<migration folder and pattern, e.g. db/NNN_*.sql>`, `<query / policy paths>`, how a migration is proven and applied: a diff touching these triggers `lens-migrations` in the lens inspection, and every migration needs the owner's word |
| Ticket mode | `tracker` (`<Jira URL>`, keys are never minted) or `local` (the `TICKET-<nn>.md` file is the ticket; the site walk reads it instead of a URL) |
| Board publish mode | `artifact` (private page, first publish needs the owner's word) or `local` (`board.html` on disk only) |
| PR review bot | `Greptile` (a requirement: the Greptile app installed on the repo; trigger comment `@greptileai review`; `/f-greploop` on every PR, at most three rounds). `none` only with the owner's recorded reason (then §10 step 2a is skipped and every PR body says so; the description check still runs) |
| Host merge strategy | `merge commit`, `squash`, or `merge commit pushed by the foreman (lane mode)` (`METHOD.md` §10 step 3 verifies accordingly; lane mode lands through `snippets/land_tested.sh`) |
| Plan check seats | `<the owner's standing pick for /f-plancheck, as roster ids, e.g. sol (codex CLI, $0) · gemini-hydrogen-agy (agy CLI, $0; gemini-hydrogen on OpenRouter, metered, without agy) · qwen4-max (OpenRouter, metered), with its date>`: written by the first plan check from the owner's first pick in the picker; the plan check then runs without asking. Say "change the plan check seats" to pick again, or "use the picker this time" for one run |
| Framework check | `<a skill that checks a plan against the framework the product is built on: /deep with the Deep Agents add-on, another you name, or none>`: run with the ground investigation at every end game that has a next job (`METHOD.md` §10 step 7b) |
| Foreman launch command | `<how you start a foreman session here, with your usual flags, e.g. claude>`: the night shift uses it to open each job's foreman |
| Master builder launch command | `<how a night shift starts a master builder session here>`, or empty for the foreman launch command. The command and flags only: the model it runs is set in the owner's own setup, never in this file (`RULES.md`: never name the builder) |
| Runs on | `<your computer (Windows / macOS / Linux)>` or `<a Linux server through Orca (SETUP.md §8b)>`. On a server: no `sudo` (anything to install system-wide: stop and ask the owner), no browser extension (browser work uses Orca's browser: `orca tab create`, `snapshot`, `click`), no Playwright |
| Names kept out of records | the path of a **git-ignored** file holding them, one name per line, matched as a whole word, case-insensitive (default `scratch/names-kept-out.txt`), and of a git-ignored **allowed contexts** file (default `scratch/names-allowed.txt`: folder names, skill paths and gate lines that contain a name by design, e.g. a tool's own folder): `skills/f-signoff/names-check.mjs` checks every staged record at the records push (`METHOD.md` §10 step 9), and `/f-signoff` makes an early pass. The names themselves never go in a tracked file, this one included (RULES: never name the builder) |
| CI runner shape | `<what the CI runner's image has and lacks that the product depends on (e.g. "glib, no libEGL"), so the local Linux check reproduces it; or "not recorded">` |
| Builder delivery | `hand-carried pointer`, `pane link (pi)`, `pane link (claude-code)` or `pane link (agy)` (Orca: `orca-pi-connect`; a plain `pane link` means Pi). The Claude Code builder's model lives in `~/.claude/foreman-builder/settings.json` and the agy builder's in `~/.gemini/foreman-builder/config.json`, never here |
| Builders | `standard = <delivery>`, `strong = <delivery>` (each one of the deliveries above), and which is the **default** for autonomous runs and night shifts; or `one builder` (the difficulty rating is still recorded and checked). Labels only: the models stay in the owner's setup, never here. Two builders on the same delivery: the owner sets the model in their setup before the pre-flight. `METHOD.md` §2 step 3a picks between them |
| Logbook upkeep every | `<n>` closes (default 10): `/f-signoff` Step 3.2a applies a guarded dream and writes a distill preview every n closes; the catch-up runs at every close |
| Max work orders per job | `<n>` (default 9): a plan counting more is split at scoping (`METHOD.md` §13: attended, on the owner's word; under an autonomous run, `RULES.md` "Its own job's split"). A repo whose jobs overrun their plans may set it lower |
| Lanes | `none` (one lane, the default: everything in lane mode is off), or `A = <hostname> (<capabilities>)`, `B = <hostname> (<capabilities>)`, capabilities from the list in `skills/f-schedule` (`screen`, `browser`, `owner`, `windows`, `macos`, `linux`, `docker`, `postgres`, `gpu`, `reach:<name>`), with the owner's words that switched lanes on and their standing word for the coordination-branch pushes (`RULES.md` act 7). Moving a lane to another machine, or changing a machine's list, is the owner's word, only while that lane has no job in progress and no end game open. `/f-schedule` copies the capabilities onto the board (`project.lane_caps`) |
| Cutting a plan (`/f-schedule` v2) | **noise files** `<files every job appends to, e.g. CHANGELOG.md, README.md>` (never block two jobs running side by side); **hot files** `<registries, shared helpers, files many tests pin, or none>` (each a barrier named after the file); **re-proof allowance** `<n>` whole work orders, default 2 (one more final round for a job that lands second). `/f-schedule` copies these and "Max work orders per job" onto each board it cuts (`project.cut`), at the cut and at every re-cut |
| Budgets per job | max repair work orders `<n>` (default 3 per task), wall time `<h>`, foreman tokens `<n>`; exhausting one → HALT, re-scope or switch builder (a switch is logged when it happens, and the close marks the difficulty check `not valid`) |
| Standing grant (acts 8 and 9) | `none` (the default), or the owner's own words, quoted; `RULES.md` "A standing grant for acts 8 and 9" |
| Blocker fixes | what an autonomous run may use to clear a blocker in the environment (`RULES.md`): **pages** `GitHub Actions budget (github.com/settings/billing/budgets)` (the default, for a personal account; an organization's repo names `github.com/organizations/<org>/settings/billing/budgets`; changed in the owner's signed-in browser, never a payment or card page); **fallbacks** `none` (or one that changes only the job's own run, e.g. a second review seat; never a setting others share, such as a repo-wide Actions variable) |
